# README AI Copilot Context

## 1. Project Overview
This repo contains the Fleet Dashboard / Vision Command web experience for a driver monitoring and road-risk demo. The dashboard consumes completed `TripData` JSON generated by local AI / BTC-style telemetry and exposes fleet monitoring, ranking, trip replay, reporting, and AI Copilot explanations.

Main screens/components:
- Overview / Map: `SE/FE/src/components/FleetMapView.tsx`, selected trip overview, summary telemetry, risk explanation.
- Monitor / Live Cam: `SE/FE/src/components/VehicleLiveView.tsx`, live or saved snapshot display.
- Trip Detail: `SE/FE/src/components/TripDetailView.tsx`, trip telemetry replay and live/saved AI fields.
- Insights: `SE/FE/src/components/PerformanceInsightsView.tsx`, currently fleet-wide performance insight across loaded trips.
- Ranking: `SE/FE/src/components/DriverRankingView.tsx`, canonical ranking table and selected-trip ranking sidebar.
- Ranking analysis: `SE/FE/src/components/DriverRankingAnalysisPage.tsx`, audit breakdown for one trip.
- AI Copilot: `SE/FE/src/components/AICopilotDrawer.tsx` plus Express APIs in `SE/FE/server.ts`.
- Executive / Copilot report: `SE/FE/src/components/CopilotFleetReportPage.tsx` plus canonical report model in `SE/FE/src/reportModel.ts`.

## 2. Tech Stack
- Frontend: React + TypeScript + Vite. Entry/root state is in `SE/FE/src/App.tsx`.
- Styling: Tailwind-style utility classes; global styles in `SE/FE/src/index.css`.
- Charts: `recharts`, used in `PerformanceInsightsView.tsx`, `DriverRankingView.tsx`, `DriverRankingAnalysisPage.tsx`, `TripDetailView.tsx`.
- Icons: `lucide-react`.
- Frontend server/API: Express server in `SE/FE/server.ts`, run through `tsx server.ts`.
- Backend/API: separate FastAPI backend in `SE/BE/app/main.py`, live alerts/snapshots consumed by FE.
- AI providers:
  - AWS Bedrock bearer-token flow in `SE/FE/server.ts`, `callBedrockConverse()`.
  - Gemini fallback via `@google/genai` in `SE/FE/server.ts`, `getGeminiClient()`.
  - Local AI / JSON telemetry is authoritative for scores and metrics.
- Local persistent data: completed trip JSON under `SE/FE/src/data/saved_trips/{trip_id}.json`.

## 4. Current Data Model
- Fleet: implicit array `vehicles: TripData[]` in `App.tsx`.
- Vehicle: not a separate entity. The UI often treats each `TripData` as a vehicle row. This is a semantic risk.
- Driver: not a robust identity. `driver_summary.subject_id` can be `T01-Sample` or `runtime`; `resolveDriverName()` in `reportModel.ts` falls back to `trip_id`.
- Trip: `TripData` in `types.ts`, with `trip_id`, `metadata`, `driver_summary`, `trip_aggregate`, `events_log`, `frames`.
- Dataset sample: `T01-Sample` through `T06-Sample` are trip IDs and are also displayed as driver/vehicle labels in some UI. This is mixed semantics.
- Frame: one telemetry row in `TripData.frames`; includes ego, driver, TTC/headway, behavior flags, and risk.
- Risk: `Frame.risk.final_risk_score` is the authoritative local AI frame risk.
- Driver state: `Frame.driver.state`, common values include `alert`, `distracted`, `drowsy`, `yawning`, `microsleep`.
- TTC: `Frame.min_ttc`, with `Infinity` or large values meaning no low-TTC risk.
- Headway: `Frame.headway_sec`.
- Behavior flags: `Frame.behavior_flags.harsh_brake`, `harsh_accel`, `harsh_corner`, `speeding`, `tailgating`.
- Event log: `TripData.events_log`, but most ranking/report code derives events from frames instead of relying on this array.

Important semantic issue: `T01-Sample/T02-Sample` are currently used as trip, driver display name, and sometimes vehicle in UI copy. There is no stable separate `vehicle_id` model in `types.ts`.

## 6. Canonical Scoring Logic
Canonical source: `SE/FE/src/components/DriverRankingView.tsx`, function `buildRankingRows()`.

Ranking Score = Base Score - Total Penalty

Base Score: `100`

Clamp: `clamp(value) = Math.max(0, Math.min(100, value))`

Additional cap: if `distractedPct > 50`, calculated score is capped at `58`.

Final score: `score = clamp(calculatedScore)`.

Penalty breakdown:
| Factor | Formula | Weight | Example |
|---|---|---:|---|
| Average Risk Penalty | `avgRisk * 0.45` | 0.45 | T01 avg risk 68.5 -> 30.8 pts |
| Max Risk Penalty | `maxRisk * 0.20` | 0.20 | max risk 100 -> 20.0 pts |
| Critical Frame Penalty | `criticalEventPct * 0.15` | 0.15 | critical frames / total frames * 100 * 0.15 |
| Distracted Penalty | `distractedPct * 0.10` | 0.10 | T01 distracted 49.6% -> 5.0 pts |
| Fatigue Penalty | `fatigueEventPct * 0.05` | 0.05 | fatigue frames / total frames * 100 * 0.05 |
| Speeding Penalty | `speedingPct * 0.03` | 0.03 | speeding frames / total frames * 100 * 0.03 |
| Tailgating Penalty | `tailgatingPct * 0.04` | 0.04 | tailgating frames / total frames * 100 * 0.04 |
| Harsh Behavior Penalty | `harshEventPct * 0.03` | 0.03 | harsh events / total frames * 100 * 0.03 |
| Near Miss Penalty | `nearMissPct * 0.05` | 0.05 | low-TTC frames / total frames * 100 * 0.05 |

Metric source priority in `buildRankingRows()`:
- If `frames.length > 0`, derive everything from frames.
- If no frames, fallback to `trip_aggregate` and `driver_summary`.

Possible score mismatch sources:
- `trip_aggregate.safe_driving_score` exists but is not used by `buildRankingRows()`.
- `liveTripData.ts` computes/caps `safeDrivingScore` separately for live sessions.
- `server.ts` has server-side `buildCopilotRankingRow()` with a duplicated scoring implementation.
- `CopilotFleetReportPage.tsx` and `reportModel.ts` call `buildRankingRows()`, so these are closer to canonical.

## 7. Severity / Safety Classification Rules
Canonical score label source: `DriverRankingView.tsx`, `scoreLabel()`.

| Level | Rule | Source file |
|---|---|---|
| CRITICAL | `score < 45` | `SE/FE/src/components/DriverRankingView.tsx` |
| AT_RISK | `score >= 45 && score < 65` | `SE/FE/src/components/DriverRankingView.tsx` |
| WATCH | `score >= 65 && score < 82` | `SE/FE/src/components/DriverRankingView.tsx` |
| SAFE | `score >= 82` | `SE/FE/src/components/DriverRankingView.tsx` |

Other thresholds:
| Rule | Meaning | Source file |
|---|---|---|
| `risk.final_risk_score >= 80` | High-risk/critical frame in ranking | `DriverRankingView.tsx`, `PerformanceInsightsView.tsx` |
| `min_ttc > 0 && min_ttc <= 2.5` | Low TTC / near miss frame | `DriverRankingView.tsx`, `reportModel.ts`, `TripDetailView.tsx` |
| `risk >= 70 || state === microsleep || low TTC` | Danger safety event | `reportModel.ts` |
| `risk >= 40 || drowsy/yawning/distracted || behavior flag` | Warning safety event | `reportModel.ts` |
| `score < 60 || fatigueEvents > 0 || distractedPct > 30` | `COACHING_24H` | `reportModel.ts` |
| `score < 80 || distractedPct > 15 || nearMissCount > 0` | `WARNING` | `reportModel.ts` |

Threshold not explicitly defined: a direct absolute severity rule based only on max risk, independent of ranking score. Max risk contributes penalty but does not directly override `riskLevel` in canonical `scoreLabel()`.

## 10. AI Copilot Problems Found
- Duplicated scoring source: `DriverRankingView.tsx` has canonical `buildRankingRows()`, while `server.ts` has separate `buildCopilotRankingRow()`. This can cause Copilot card scores to drift from Ranking.
- Mixed semantics: UI and prompts still use `driver`, `vehicle`, and `trip` interchangeably. Current data is trip-level.
- Maintenance telemetry is limited. `reportModel.ts` can estimate brake/tire stress from safety events and only reads real DTC from `obd`, `vehicle_health`, or `trip_aggregate.dtc_codes`; true vehicle-health telemetry is otherwise not present.
- `trip_aggregate.safe_driving_score` exists and may differ from Ranking Score. Copilot must not use BTC safe score as ranking unless explicitly labeled.
- `liveTripData.ts` computes `safeDrivingScore` separately and caps it based on risk; this is another score source.
- `/api/copilot/report` validates Bedrock output, but Bedrock can still be too brief or operationally vague if prompt/input is too compact.
- If fatigue, distracted, near miss, or harsh behavior are zero, Copilot must not invent actions around those metrics.
- Report code contains local narrative and loading states. This is okay if labeled JSON/local AI, but must not be confused with Bedrock insight.
- Language mix exists: many UI/report sections use English headers with Vietnamese body.
- `Best driver` wording should be avoided; current newer UI uses `Lowest-risk trip` in some places, but all older labels should be audited.

## 11. Target AI Copilot Behavior
AI Copilot must not recalculate score if canonical ranking data is already supplied. It should use `buildRankingRows()` output or a shared derived payload as the single source.

AI Copilot must distinguish:
- Relative ranking: `#1` means highest Ranking Score within currently loaded fleet.
- Absolute safety: `CRITICAL` means still unsafe even if ranked #1.
- Driver behavior risk: distracted, fatigue, speeding, tailgating, harsh behavior.
- Traffic/environment/local AI risk: high `risk.final_risk_score`, max risk, critical frames.
- Data unavailable: no maintenance telemetry, no DTC, missing GPS/camera/live data.

For maintenance questions without vehicle-health telemetry, Copilot should answer:
“Hiện chưa có vehicle-health telemetry để kết luận bảo trì. Tôi có thể ưu tiên xe/chuyến cần review an toàn dựa trên driving-risk data.”
